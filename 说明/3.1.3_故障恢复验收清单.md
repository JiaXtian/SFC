# 3.1.3 故障恢复与容错处理验收清单（阶段5）

## 1. 故障注入能力
- [ ] 支持节点故障注入（低概率，按 tick 注入）。
- [ ] 支持链路故障注入（低概率，按 tick 注入）。
- [ ] 支持故障自动恢复（TTL 到期恢复）。
- [ ] 前端事件流可见 `fault_event` / `recovery_event`。

## 2. 重调度与容错策略
- [ ] 检测到故障/异常后，在线会话触发重算（非每 tick 重算）。
- [ ] 输出恢复策略类型：`local_reroute` / `cross_node_redeploy` / `hold_and_observe` / `degraded_fallback`。
- [ ] 重算结果包含成功/失败状态，并写入事件流。
- [ ] 路径高亮在重调度后自动联动更新。

## 3. 指标与统计
- [ ] 提供本 tick 恢复尝试/成功/失败统计。
- [ ] 提供累计恢复尝试/成功/失败统计。
- [ ] 提供恢复成功率 `recovery_success_rate`。
- [ ] 提供编排时延统计（mean/p50/p95/p99）。

## 4. 可视化与回放
- [ ] 监控页面可查看故障-恢复全过程。
- [ ] 可查看在线会话状态、手动触发重算、停止会话。
- [ ] 可查看故障恢复 KPI 与趋势图（时延、带宽利用率、故障链路）。

## 5. 验收口径
- 恢复成功：故障触发后会话重算返回 `deployed/redeployed/stable`。
- 恢复失败：故障触发后会话重算返回 `decision_failed` 或无候选。
- 受影响业务量：本实现按会话粒度统计，单次恢复事件默认 `affected_services=1`。

## 6. 回归建议
- 固定随机种子，执行 30 分钟回放。
- 对比故障开启/关闭两组：
  - 恢复成功率
  - 恢复平均时延
  - 累计失败数
  - 业务连续性（是否持续有可用候选）
