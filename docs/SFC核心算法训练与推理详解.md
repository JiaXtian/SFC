## 2. 问题定义与优化目标

### 2.1 编排问题定义

给定：

- 动态卫星网络拓扑图 `G=(V,E)`，节点含算力/内存/磁盘/可靠性，链路含带宽/时延/状态/可靠性。
- 一个 SFC 请求 `R`，包含有序核心网网元序列（如 AMF/SMF/UPF...）及 SLA 约束。

目标：

- 为每个核心网网元选择部署节点与中间路径，满足资源、连通性、带宽、时延、可靠性约束。
- 在满足 SLA 的前提下，尽可能提升成功率、降低时延、控制路径跳数与资源热点。

### 2.2 多目标本质

系统是带硬约束的多目标优化：

- 主目标：编排成功率、SLA 满足率
- 次目标：端到端时延、算法决策时延、负载均衡
- 约束：资源容量、带宽容量、链路可用、可靠性、路径跳数上限

## 3. 训练侧核心算法

## 3.1 训练数据生成（拓扑 + 请求）

数据生成由 `train/training/data_generation` 完成，核心思想是构造多尺度、多负载、多业务类型样本：

- 拓扑：生成不同规模轨道网络（中小规模 + 大规模）
- 请求：生成多种业务链模板（basic/auth/slice/full 等）
- 标签不显式监督：采用环境交互奖励做强化学习

训练脚本会构造 scale-balanced 训练数据池，避免单一规模主导学习。

## 3.2 状态与特征建模

### 3.2.1 节点特征（14维）

训练与新推理模型使用 14 维节点特征（`trainer.py::_get_graph_data` 与 `network_graph.cpp::get_node_features` 对齐）：

1. CPU 可用比
2. MEM 可用比
3. DISK 可用比
4. 综合核心网负载
5. 节点可靠性
6. 出边激活率
7. 出边带宽可用比
8. 出边平均时延归一化
9. signaling 负载
10. session 负载
11. user-plane 负载
12. mobility 负载
13. policy 负载
14. auth 负载

### 3.2.2 核心网网元特征（8维）

`trainer.py::_build_vnf_features` 与 C++ `build_core_nf_features` 对齐：

1. CPU 需求
2. MEM 需求
3. 带宽需求
4. DISK 需求
5. 是否用户面（UPF）
6. 是否控制面
7. 是否状态型
8. 处理权重

### 3.2.3 上下文特征（默认48维）

`trainer.py::_build_context_features` 构造，前 22 项为核心业务与 SLA 关键态势，其余可扩展。

关键字段包括：

- 剩余时延预算、当前网元索引、业务负载指数
- 可靠性需求与已累计可靠性
- 累积时延、可靠性裕度
- 动态拓扑健康指标（可用节点比例、可用链路比例等）

## 3.3 启发式候选剪枝（Heuristic Pruner）

强化学习不直接在全图节点上做动作，而是先剪枝再决策：

- 根据资源可行性、带宽可行性、可达性、时延预算、跳数预算筛候选
- 使用受约束最短路/代价函数进行候选排序
- 输出 Top-M 候选供 Actor 选择

好处：

- 显著压缩动作空间
- 减少无效探索
- 保留强约束可解释性

## 3.4 GNN 编码器（图表示学习）

`training/models/gnn_encoder.py`：

- 输入：`node_features (N,14)` + `edge_index (2,E)`
- 结构：Input Linear -> 4 层 GCNConv + LayerNorm + GELU + Dropout + Residual
- 输出：`node_embeddings (N,192)`

设计动机：

- 用消息传递聚合邻域拓扑与链路状态
- 残差结构稳住深层传播，降低过平滑风险

## 3.5 策略网络（Actor）与价值网络（Critic）

`training/models/drl_agent.py`：

- Actor 输入：候选节点嵌入 + VNF特征 + Context特征
- 拼接维度：`192 + 8 + 48 = 248`
- Actor 输出：每个候选节点的 logits/probs
- Critic 输入：候选平均嵌入 + VNF + Context，输出状态价值

训练算法：A2C 风格（策略梯度 + 价值回归 + 熵正则）。

## 3.6 环境转移与约束验证

`environment/sfc_env.py::step` 负责执行动作并做硬约束判断：

- 节点资源约束（CPU/MEM/DISK）
- 链路可用与带宽约束
- 累积时延约束
- 累积可靠性约束
- 跳数上限约束
- 最后一跳到目的节点的收尾路径约束

任何关键约束失败会触发惩罚并结束 episode（或回滚）。

## 3.7 奖励函数设计

奖励由多个项组成（成功正奖励 + 失败惩罚 + SLA 裕度 + 负载均衡项），核心目标是：

- 鼓励逐步可行部署与最终完成
- 惩罚资源失败、路径失败、时延超限、可靠性不达标
- 对热点节点重复使用给惩罚，鼓励负载分散

## 3.8 训练稳定性机制

`train.py` 里有多项工程化稳定策略：

- `epsilon` 探索衰减
- 可靠性课程学习（从宽到严）
- 共享资源模式概率渐变
- 热身期小样本快速收敛
- 崩塌检测与回退（加载 best checkpoint）
- 联合优化（把 GNN 参数加入 Actor 优化器参数组）

这些机制共同降低训练震荡，提高可达性与收敛稳定性。

## 3.9 模型导出

`model_export.py` 导出两个 ONNX：

- `gnn_encoder.onnx`
- `actor.onnx`

并输出 `model_io_meta.json`，描述 I/O 维度元信息。

## 4. 推理侧核心算法（C++ 在线编排）

## 4.1 推理总流程

`model_benchmark/main.cpp` 主链路：

1. 加载拓扑与请求
2. 构建图特征（节点特征 + edge_index）
3. GNN 一次编码生成节点嵌入
4. 每个请求逐网元执行：
   - 启发式剪枝产出候选
   - Actor 选首选节点
   - 约束检查 + 路径搜索 + 回退探测（最多若干候选）
5. 汇总成功率、时延、失败原因、分规模统计

## 4.2 C++ 推理中 DRL 的角色

不是“纯黑盒一票否决”，而是“学习排序 + 规则约束”协同：

- DRL：在候选集合内给优先级
- 启发式/约束：保证可行性、安全性、可解释性
- 回退逻辑：当 DRL 首选不可行时，继续尝试后续候选

## 4.3 路径与可靠性处理

在线推理阶段会累积：

- 端到端时延（路径传输 + 处理近似）
- 端到端可靠性（节点可靠性 × 链路可靠性）

并在每一步检查未来可行性（optimistic future reliability）。

## 7. 复杂度与性能分析

## 7.1 主要计算开销

- GNN 编码：约 `O(E * L)`（L 为 GCN 层数）
- 剪枝与路径搜索：每步近似 `O((|E|+|V|) log |V|)`
- Actor 推理：`O(M * d)`（M 为候选数，d 为拼接特征维度）

## 7.2 工程性能策略

- 先剪枝再决策，降低动作空间
- 训练时部分 bootstrap 复用图嵌入，减少重复 GNN 前向
- 推理中先 DRL 首选，再受限回退，平衡速度与可行性

## 8. 适用性、局限与改进方向

## 8.1 当前优势

- 强约束可解释（资源/时延/可靠性/跳数）
- 学习策略与启发式协同，泛化较稳定
- 具备旧模型兼容能力，部署韧性更高

## 8.2 已知局限

- 兼容旧模型通过“截断/补零”实现，能跑但非最优语义对齐
- 大规模拓扑下，路径搜索仍是主耗时来源
- 不同数据分布下成功率可能波动，依赖训练集覆盖度

## 8.3 后续建议

1. 在导出模型中强制写入并校验元数据版本（含 feature schema hash）。
2. 将推理日志中的“特征适配命中率”纳入监控，尽早发现模型漂移。
3. 对旧模型兼容路径增加一次离线评估门槛，避免性能回退不透明。
4. 进一步把路径搜索并行化/缓存化，降低大图 P95。

## 10. 结论

本系统核心算法采用“**启发式可行性约束 + GNN 图表示 + Actor-Critic 策略优化**”的混合架构，既保证工程可落地性，又具备学习驱动的策略改进能力。

本次修复后，系统已同时具备：

- 正确模型目录选择（消除新旧模型混用）
- ONNX 维度自适配（降低因版本漂移导致的不可用风险）
- 在不重训前提下恢复推理链路可运行
